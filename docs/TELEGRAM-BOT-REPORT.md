# گزارش وضعیت و عملکرد ربات تلگرام سِپفیروث

> تاریخ: 2026-10-29 · بر اساس کد v2.7.0 (Task 23-a/23-c/28) و وضعیت زندهٔ استور

---

## ۱) خلاصهٔ مدیریتی (یک خط)

**موتور ربات کاملاً ساخته شده و از نظر کد آمادهٔ کار است (فروش + اعلان + ادمین)، ولی در این نمونه هنوز تنظیم و روشن نشده — صفر ترافیک واقعی داشته است.**

---

## ۲) چه چیزی ساخته شده؟ (قابلیت‌های موتور)

| بخش | وضعیت | جزئیات |
|---|---|---|
| مُدها | ✔ | `console` (کنسول تست) / `notify` (اعلان + فرمان‌های ادمین) / `sales` (همه + فروشگاه) |
| ورکر | ✔ | Long-poll درون-پردازشی با offset ماندگار در استور، بک‌آف خطا 1s→5s→30s، گارد تک-نمونه، هرگز پنل را نمی‌اندازد |
| زبان‌ها | ✔ | ۶ زبان (fa/en/ar/zh/tr/ru) — انتخاب زبان در اولین /start |
| فروشگاه | ✔ | کاتالوگ قالب‌های فروش (نام/حجم/روز/آی‌پی/قیمت تومان + تیک نمایش در ربات) |
| پرداخت | ✔ | زرین‌پال v4 (start/verify با حلقهٔ تأیید ۶۰ ثانیه‌ای) + کارت‌به‌کارت (عکس رسید → تأیید/رد ادمین) |
| تحویل | ✔ | ساخت خودکار کلاینت پس از پرداخت (state machine ایدمپوتنت — پرداخت دوباره = دو نسخه نمی‌سازد) + لینک ساب + Clash + Sing-Box |
| تریال | ✔ | یک بار برای هر آدم تلگرامی (rate-limit دائمی) |
| اشتراک‌های من | ✔ | لیست خریدهای همان آدم + مصرف + روزهای مانده |
| فرمان‌های ادمین | ✔ | /admin /status /users /inbounds /user /backup_now /help — چکِ دسترسی روی **هر** پیام و **هر** دکمه (نه فقط فرمان) |
| کنترل سریع | ✔ | فعال/غیرفعال‌کردن کاربر، صفرکردن حجم — از دکمه‌های کارت کاربر |
| اعلان‌ها | ✔ | ۱۵ نوع رویداد با dedupe + کلیدهای on/off (ساخت/حذف/به‌روزرسانی کاربر، انقضا، سهمیه، بکاپ، ری‌استارت، اینباند…) |
| دیجست روزانه | ✔ | گزارش ۲۴ ساعته: سفارش‌ها/درآمد/کاربر جدید |
| امنیت بکاپ | ✔ | خروجی /backup_now توکن ربات را مستثنا می‌کند |
| پشتیبانی پروکسی | ✔ | HTTPS/SOCKS proxy برای api.telegram.org (برای سرورهای داخل ایران) |

## ۳) وضعیت زنده در این نمونه (اعداد واقعی استور)

| سنجه | مقدار | تفسیر |
|---|---|---|
| botMode | `console` (پیش‌فرض) | ورکر فروش/اعلان اصلاً استارت نخورده |
| توکن ربات | ذخیره نشده | بدون توکن فقط حالت کنسول |
| adminChatIds | خالی | هیچ ادمینی تعریف نشده |
| کاربران تلگرام (tgUser) | **0** | هیچ‌کس ربات را استارت نکرده |
| سفارش‌ها (tgOrder) | **0** | هیچ فروشی ثبت نشده |
| ردیف‌های activity از actor «telegram-bot» | **0** | موتور هیچ اقدامی انجام نداده |
| قالب‌های فروش (saleTemplate) | 1 | آمادهٔ نمایش در فروشگاه (تیک botVisible لازم) |
| کاربران پنل / اینباند / ریسلر | 4 / 21 / 1 | بستر فروش کاملاً آماده |

## ۴) عملکرد — صادقانه

چون ربات در این نمونه **هیچ ترافیک واقعی نداشته**، آمار عملکردی واقعی (تأخیر پاسخ، نرخ خطا، فروش) وجود ندارد و ساختِ عدد از هوا غلط است. چیزی که می‌شود با اطمینان گفت، **طراحی عملکردی** موتور است:

- حلقهٔ getUpdates ترتیبی با فاصلهٔ ۱ ثانیه → در برابر 429 تلگرام امن
- offset بعد از هر دسته ذخیره می‌شود → ری‌استارت پنل = هیچ پیامی گم نمی‌شود و دوباره هم پردازش نمی‌شود
- خطاها بک‌آف نمایی و شمارش در status worker (پیل زنده در کارت تنظیمات ربات)
- ساخت کلاینت پس از پرداخت claim اتمی دارد → حتی اگر دو مسیر (تأیید ادمین + پولر زرین‌پال) هم‌زمان برسند، دقیقاً یک بار provision می‌شود
- استور JSON با نوشتن اتمی (tmp+bak) → خرابی وسط نوشتن = دیتای سالم قبلی

**بعد از راه‌اندازی، همان کارت ربات در تنظیمات، پیل وضعیت ورکر + شمارنده‌های handled/errors را زنده نشان می‌دهد و من می‌توانم گزارش عملکرد واقعی بدهم.**

## ۵) چک‌لیست ۵ قدمی برای زنده‌کردن (حدود ۵ دقیقه کار)

1. در @BotFather یک ربات بساز و توکن را بگیر
2. پنل → تنظیمات → کارت ربات تلگرام: توکن را ذخیره کن (تست اتصال همان‌جا هست)
3. شناسهٔ تلگرام خودت را در `adminChatIds` بگذار
4. مُد را روی `sales` بگذار و `publicHost` را پر کن (آدرس عمومی پنل) — روی کاتابامپ که فرانسه است، پروکسی لازم نیست
5. قالب فروش را با قیمت و تیک «نمایش در ربات» تنظیم کن → در تلگرام `/start` بزن → فروشگاه را ببین

## ۶) شکاف‌ها (و اینکه کجا حل می‌شوند)

حذف/ساخت دستوری کاربر، ویرایش سهمیه، تمدید اشتراک، کیف پول و QR عکسی → **همین امروز در فاز ۱ نقشه راه (v2.8) شروع می‌شود.**
