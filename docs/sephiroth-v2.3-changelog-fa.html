۱. رفع اشکالات این نسخه

مهم‌ترین مشکل این نسخه، «قطع شدن» خود پنل بود؛ نه فقط لایو پریویو. دو خطای واقعی پیدا و ریشه‌ای حل شد:

CRITICAL کرش کامل سرور هنگام بوت

در نسخه ۲.۲.۰ یک مسیر API ناقص باقی مانده بود (/api/outbounds/[id]/test)؛ فایل سرور به آن ارجاع می‌داد ولی فایلش وجود نداشت. نتیجه: کل پروسه سرور موقع استارت‌آپ با خطای ERR_MODULE_NOT_FOUND کرش می‌کرد و پنل هیچ‌چیز نمایش نمی‌داد — همان «لایو پریویو قطع شده و نشون نمی‌ده». فایل ساخته شد و تست اتصال خروجی‌ها هم اکنون واقعاً کار می‌کند (دکمه Test در بخش خروجی‌ها).

CSS صفحه سفید/خالی به‌خاطر PostCSS خراب

یک فایل پیکربندی اضافه (postcss.config.mjs) به پوشه پروژه راه پیدا کرده بود که به پکیجی اشاره می‌کرد که اصلاً نصب نیست. موتور Tailwind 4 این پروژه از طریق پلاگین Vite کار می‌کند؛ فایل زائد حذف شد تا کل صفحه سفید نماند.

OK لایو پریویو الان سالم است

پیش‌نمایش زنده دیالوگ ساخت کانفیگ تست شد: با تغییر پورت، پروتکل و کلاینت، لینک اشتراک لحظه‌ای و صحیح به‌روز می‌شود (مثل vless://…@host:port?type=tcp#Sephiroth · draft).

UNIQUE FEATURES

۲. قابلیت‌هایی که بقیه پنل‌ها ندارند

سه قابلیت جدید که هیچ‌کدام از پنل‌های معروف (3x-ui، Marzban، Remnawave، S-UI و…) چیزی شبیه‌شان ندارند:

⓵ صحت‌سنج کانفیگ — Config Doctor

یک «دکتر» برای کل پنل: دکمه «صحت‌سنج کانفیگ» در صفحه کانفیگ‌ها، کل دیتابیس واقعی شما را اسکن می‌کند و یک امتیاز از ۱۰۰ به‌همراه نمره سلامت (A تا D) می‌دهد. ۱۶ سناریوی خطر را می‌گیرد و برای هر مورد یک راه‌حل مشخص پیشنهاد می‌کند:

  • پراکسی باز: اینباند SOCKS/HTTP بدون رمز روی همه اینترفیس‌ها (خطر واقعی سوءاستفاده)
  • TLS بدون گواهی و REALITY ناقص (serverNames/shortIds/کلیدها)
  • فال‌بک خراب در VLESS/Trojan و کلید خصوصی تکراری WireGuard بین اینباندها
  • رول مرده و رول همه‌چیزگیر در روتینگ (اشاره به خروجی ناموجود)
  • کاربر منقضی ولی روشن، سقف‌خورده، نزدیک انقضا/سقف، بدون کانفیگ یا وصل به اینباند خاموش
  • اینباند منقضی/خاموش و پورت‌های ممتاز (<۱۰۲۴)

⓶ پیش‌بینی اتمام ترافیک کاربر

زیر نوار مصرف هر کاربر یک چیپ هوشمند ظاهر می‌شود: «≈۵ روز تا سقف · ۱۱GB در روز». نرخ سوخت متوسط از روز ساخت حساب محاسبه می‌شود و به شما می‌گوید کاربر کِی حجمش تمام می‌شود — رنگ زرد/قرمز برای فوریت بالا. دیگر لازم نیست حدس بزنید چه کسی باید شارژ شود؛ پنل خودش پیش‌بینی می‌کند. (این قابلیت فقط وقتی نمایش داده می‌شود که کاربر سقف حجم داشته باشد و مصرف واقعی ثبت شده باشد.)

⓷ پروکسی تلگرام SOCKS5 در خود Forge

بخش بعدی را کامل بخوانید — سؤال «با پنل خودمان می‌شود پروکسی تلگرام ساخت؟» جواب قاطع دارد: بله، دو راه.

TELEGRAM PROXY

۳. پروکسی تلگرام: SOCKS5 یا MTProto؟

جواب کوتاه: بله، با همین پنل هر دو شدنی است. تلگرام دو نوع پروکسی می‌فهمد:

SOCKS5 (جدید — در Forge)MTProto (ابزار تنظیمات)
سرعتبسیار سریع (پروکسی ساده TCP)سریع
پوشش/استتارندارد — قابل شناسایی توسط DPIسکرت dd رمزنگاری‌شده شبیه ترافیک HTTPS
راه‌اندازی در پنلForge ← پروتکل SOCKS ← بلوک خودکار تلگرامتنظیمات ← ابزار MTProto (سکرت + لینک‌ها + دستور mtg)
بهترین کاربردفیلترینگ معمولی، اینترنت خانگی/اداریشبکه‌های سرکوبگر و DPI فعال (ایران)

راه SOCKS5 — سه قدم، داخل خود پنل:

  1. ساخت کانفیگ جدید ← پروتکل SOCKS را انتخاب کنید و یک پورت آزاد بدهید (مثلاً 10808).
  2. در همین صفحه، بخش «پروکسی تلگرام (SOCKS5)» خودش ظاهر می‌شود: نام کاربری/رمز بگذارید تا لینک‌ها امن شوند.
  3. لینک https://t.me/socks?… را کپی کنید یا QR را با گوشی اسکن کنید — تلگرام خودش پروکسی را اضافه می‌کند. تمام!

شکل لینک تولیدی

https://t.me/socks?server=YOUR-SERVER&port=10808&user=ali&pass=Xy91kQ
tg://socks?server=YOUR-SERVER&port=10808&user=ali&pass=Xy91kQ

کلاینت تلگرام هر دو را می‌فهمد؛ لینک t.me برای فرستادن به دوستان و QR برای اسکن حضوری بهترین‌اند.

HONEST نکته صادقانه درباره SOCKS5

SOCKS5 هیچ پوششی ندارد؛ در شبکه‌هایی که DPI فعال دارند (مثل ایران) قابل شناسایی و مسدودسازی است. برای آن شرایط، از ابزار MTProto در تنظیمات استفاده کنید: سکرت dd تولید می‌شود و دستور آماده اجرای دیمن mtg را می‌دهد. نکته مهم: Xray از نسخه v24.10 اینباند mtproto داخلی را حذف کرده، پس MTProto به یک پورت TCP خام جداگانه و یک دیمن کوچک نیاز دارد — پنل همه دستوراتش را آماده تحویل می‌دهد.

۴. کتابامپ: حذف کامل و نصب آخرین نسخه

چون نسخه قبلی روی کتابامپ همین باگ بوت را داشت، بهترین راه یک نصب تمیز است — نه آپدیت روی نسخه خراب:

  1. از داده‌های فعلی یک بکاپ بگیرید (اگر چیزی مهم دارید): در پنل فعلی ← تنظیمات ← بکاپ ← دانلود فایل JSON. اگر پنل قبلاً بالا نمی‌آید، این مرحله را رد کنید.
  2. پنل قدیمی را کاملاً حذف کنید: در داشبورد کتابامپ، اپلیکیشن Sephiroth را انتخاب و Delete کنید. اگر گزینه «پاک کردن کامل فایل‌ها/دیتابیس» داشت، آن را هم بزنید تا هیچ فایل قدیمی نماند.
  3. آخرین نسخه را بگیرید: از صفحه GitHub عمومی (Edsel-Rahimi/sephiroth) بخش Releases، فایل ZIP سورس نسخه 2.3.0 را دانلود کنید (یا برنچ main).
  4. در کتابامپ دوباره Deploy کنید: Create App ← آپلود ZIP یا آدرس مخزن ← تنظیمات پیش‌فرض (پورت ۳۰۰۰ ← Start command همان npm run start/bun run start که قبلاً بود).
  5. بعد از اولین بوت: با admin / sephiroth وارد شوید و فوراً از پروفایل، رمز را عوض کنید. بعد تنظیمات ← بخش‌های بکاپ/۲FA را روشن کنید.
  6. بازیابی بکاپ (اختیاری): تنظیمات ← Restore ← همان فایل JSON مرحله ۱.

راه دوم — بدون حذف (آپدیت از داخل خود پنل)

از نسخه ۲.۲ به بعد، پنل دکمه بروزرسانی خودکار دارد: تنظیمات ← Software Update ← «Check for updates». چون نسخه فعلی کتابامپ شما (۲.۲.۰) به‌خاطر باگ بوت بالا نمی‌آید، این‌بار از مسیر نصب تمیز بروید؛ از دفعه بعد همین دکمه کار را یک‌کلیکی می‌کند.

ONE PORT

۵. چند پروتکل روی یک پورت (یادآوری)

از نسخه ۲.۲: در دیالوگ ساخت سریع، کاشی «کمبو تک‌پورت» با یک کلیک این را می‌سازد:

  • پورت اصلی: VLESS + TLS روی پورت عمومی (مثلاً 10000)
  • فال‌بک اول: مسیر /panel ← خود پنل (همان پورت، بدون پورت اضافه)
  • فال‌بک دوم: بقیه ترافیک ← تروجان داخلی روی 127.0.0.1:10001

یعنی کلاینت‌های VLESS و Trojan هر دو از «یک پورت» سرویس می‌گیرند و nobody نمی‌فهمد پشت آن چه خبر است. در Forge هم تب «پیشرفته» اجازه می‌دهد فال‌بک‌ها را دستی ویرایش کنید و JSON سرور را کپی بگیرید.
