۰۱ · خلاصه‌ی تغییرات نسخه ۲.۲

هر هفت قابلیت زیر بر اساس «تحلیل شکاف» از بررسی عمیق ۷ پنل رقیب (3x-ui، Marzban، Marzneshin، Hiddify، S-UI، x-ui، Remnawave) پیاده‌سازی شده‌اند؛ اولویت‌بندی از گزارش docs/panel-gap-analysis.md برداشته شد و همه در ۶ زبان پنل ترجمه شده‌اند.

۱ دکمه‌ی بروزرسانی پنل

تنظیمات → بروزرسانی نرم‌افزار: چک نسخه از مخزن عمومی گیت‌هاب، مقایسه‌ی نسخه، آپدیت یک‌کلیکی (git fetch + reset + install در پس‌زمینه) و دکمه‌ی ری‌استارت. دقیقاً همان الگویی که 3x-ui دارد.

۲ بکاپ خودکار روزانه

بکاپ کامل وضعیت پنل روی خودِ سرور در db/backups/ هر ۲۴ ساعت؛ نگهداری آخرین N فایل، لیست فایل‌ها با دانلود و حذف، زمان آخرین اجرا و دکمه‌ی «همین حالا بکاپ بگیر».

۳ ورود دومرحله‌ای TOTP

فعال‌سازی با QR (Google Authenticator / Aegis / Authy)؛ پیاده‌سازی RFC-6238 بدون هیچ وابستگی جدید. غیرفعال‌سازی و فعال‌سازی مجدد فقط با کد معتبر — حتی با نشست باز نمی‌شود 2FA را بی‌صدا خاموش کرد.

۴ پروکسی MTProto تلگرام

کارت اختصاصی در تنظیمات: ساخت سکرت FakeTLS (dd) یا ساده، لینک‌های tg://proxy و t.me/proxy با کپی فوری + دستورات آماده‌ی اجرا (mtg v2 و erlang MTProtoProxy).

۵ کمبو تک‌پورت

پریست جدید در «ساخت سریع»: روی یک پورت عمومی VLESS+TLS می‌سازد با Fallback به تروجان داخلی و مسیر /panel برای خود پنل — چند پروتکل، یک پورت (بخش ۰۳ همین سند).

۶ فرمت اشتراک Xray-JSON

خروجی کامل کانفیگ کلاینت Xray/v2ray-core از آدرس اشتراک با ?format=xray (vless/vmess/trojan/shadowsocks + TLS/Reality + ws/grpc/xhttp) + دکمه‌ی «کپی JSON سرور» در تب پیشرفته‌ی Forge.

پاک‌سازی کامل دمو (نسخه ۲.۱.۱): هیچ داده‌ی فیک در پنل نیست — هیچ اینباند نمونه، کاربر تزئینی یا عدد ساختگی. همه‌ی اعداد داشبورد واقعی اند (CPU/RAM/دیسک/شبکه‌ی واقعی سرور) و ورود اول = تجربه‌ی «اولین بار» تمیز.

۰۲ · چند پروتکل روی «یک» پورت — توضیح ساده

سوال: روی کتابامپ فقط یک پورت داریم که برای VLESS است. چطور پروتکل‌های دیگر را هم بالا بیاوریم؟ جواب کوتاه: پورت فقط یک «در» است؛ مهم این است که بعد از باز شدن در، بر اساس محتوای ترافیک تصمیم بگیریم کدام پروتکل آن را باز کرده است.

پورت ۴۴۳تنها درِ باز
VLESS + TLS — صاحب اصلی پورت؛ TLS را باز می‌کند
Trojan — ترافیک غیر VLESS به آن منتقل می‌شود
پنل وب — مسیر /panel به خود پنل می‌رسد
هر مسیر دیگر — با path/alpn قابل تعریف
۱ · اتصال می‌رسدکلاینت به همان یک پورت وصل می‌شود و TLS handshake انجام می‌شود
←
۲ · VLESS بررسی می‌شوداگر ترافیک VLESS معتبر بود → همین‌جا سرو می‌شود
←
۳ · Fallbackاگر نبود، Xray بر اساس SNI/ALPN/Path تصمیم می‌گیرد: تروجان؟ پنل؟ وب؟

در پنل چطور؟ کانفیگ‌ها → ساخت سریع → کاشی «کمبو تک‌پورت» → بساز. پنل خودش دو اینباند می‌سازد:

  • اینباند اصلی — VLESS + TCP + TLS روی پورت عمومی (مثلاً ۱۰۰۰۰) با دو Fallback: مسیر /panel به پنل، و بقیه‌ی ترافیک به تروجان داخلی.
  • اینباند داخلی — Trojan روی 127.0.0.1:10001 (فقط localhost؛ از بیرون دیده نمی‌شود).
  • خروجی آماده — در تب «پیشرفته» دکمه‌ی «کپی JSON سرور» همان کانفیگ واقعی Xray را می‌دهد؛ روی سرور واقعی‌ات داخل inbounds کانفیگ paste کن — همان یک پورت، چند پروتکل.
نکته‌ی مهم درباره‌ی کتابامپ: اگر پورت کتابامپ مستقیم به پروسه‌ی پنل می‌رسد (HTTP)، برای اجرای واقعی Xray به یکی از این سه راه نیاز داری: ① پلتفرمی که پورت خام TCP بدهد (VPS/اسکیل)، ② پنل + VLESS روی همان یک پورت با همین الگوی Fallback روی سرور شخصی، ③ تانل: سرور خارجی پورت را باز می‌کند و با dokodemo-door یا تانل (بخش تانل‌های پنل) ترافیک را به هاست تو می‌رساند.

۰۳ · پروکسی MTProto برای تلگرام

از تنظیمات ← کارت «پروکسی MTProto (تلگرام)»: هاست/آی‌پی و پورت را بده، «ساخت سکرت» را بزن — سکرت FakeTLS (پیشوند dd؛ شبیه ترافیک TLS عادی و مقاوم‌تر به فیلترینگ) یا ساده می‌سازد و لینک‌های دعوت را همان لحظه می‌دهد:

# لینک‌های خروجی (کپی با یک کلیک):
tg://proxy?server=HOST&port=443&secret=dd...
https://t.me/proxy?server=HOST&port=443&secret=dd...

اجرا روی سرور — دکمه‌ی «راه‌اندازی سرور» دو دستور آماده می‌دهد؛ ساده‌ترین راه دیمن mtg است:

# mtg v2 — FakeTLS (توصیه‌شده)
docker run -d --name mtg --restart=always -p 443:3128 \
  ghcr.io/9seconds/mtg/v2:latest simple-run -n 16 \
  "$(docker run --rm ghcr.io/9seconds/mtg/v2:latest generate-secret tls -c cloudflare.com)"

# یا erlang MTProtoProxy با سکرتِ ساخته‌شده در پنل
docker run -d --name mtproxy --restart=always -p 443:443 \
  -e SECRET=dd... seriyps777/mtproto-proxy:latest
صادقانه بگوییم: هسته‌ی Xray از نسخه‌ی v24.10 به بعد پروتکل mtproto را حذف کرده؛ به همین دلیل پنل به‌جای اینباند mtproto، «مولد سکرت/لینک + دستورات دیمن اختصاصی» می‌دهد. MTProto به یک پورت TCP خام نیاز دارد — روی هاست‌های تک‌پورتی (مثل کتابامپ) یا باید یک پورت دوم بگیری، یا با روتینگ SNI روی سروری که کنترل کامل داری. ضمناً این پروکسی را باید روی یک سرور واقعی (VPS خارج) اجرا کنی؛ سکرت و لینک از همین کارت قابل کپی است و بلافاصله در تلگرام کار می‌کند.

۰۴ · بروزرسانی پنل در کتابامپ — سه راه

  • داخل خود پنل (جدید): تنظیمات ← بروزرسانی نرم‌افزار ← «بررسی بروزرسانی». اگر نسخه‌ی جدیدی در مخزن باشد دکمه‌ی «همین حالا بروزرسانی کن» ظاهر می‌شود؛ بعد از اتمام، «ری‌استارت پنل» را بزن. (نیازمند نصب از نوع git clone)
  • اگر با ZIP آپلود کرده‌ای: کارت بروزرسانی خودش تشخیص می‌دهد و راهنمایی می‌کند — آخرین نسخه را از github.com/Edsel-Rahimi/Sephiroth به‌صورت ZIP بگیر و مثل دفعه‌ی قبل آپلود/جایگزین کن؛ پوشه‌ی db/ را دست نزن تا اطلاعات بماند.
  • خط فرمان ( اگر دسترسی SSH داری): git fetch origin && git reset --hard origin/main && (bun install || npm install) و ری‌استارت پروسه.
