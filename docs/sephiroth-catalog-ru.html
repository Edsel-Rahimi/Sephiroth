SECTION 01 — INTRODUCTION

01Введение — что такое Sephiroth?

Sephiroth — полноценная панель управления для Xray: inbound-ы, пользователи и подписки, живая статистика, безопасность и бэкапы — всё в едином процессе Node.js. Ни MySQL, ни Postgres не нужны; данные хранятся в одном атомарном JSON-файле, и интерфейс обслуживается с того же порта.

Sephiroth создан для администраторов личных серверов с точным контролем, для продавцов с реселлерской системой и шлюзами и для self-hosting-любителей, которым нужна красивая, лёгкая панель на своём языке — с телеметрией Socket.IO, палитрой Ctrl+K и полевым справочником.

SECTION 02 — ARCHITECTURE

02Архитектура панели

Вся панель — один процесс: сервер Express (REST API) обслуживает тот же порт, на котором работает собранный React-интерфейс (SPA), а Socket.IO рассылает живую телеметрию (CPU/RAM/диск, состояние inbound-ов, события). У сетевого ядра два режима: Симулятор (по умолчанию; безопасный, без бинарников) или реальный драйвер Xray (подробно в разделе 07).

SECTION 03 — AMNEZIAWG · OBFUSCATED WIREGUARD

03AmneziaWG — WireGuard, устойчивый к цензуре

AmneziaWG — тот же WireGuard с суперсилой: самодельные пакеты и кастомные «магии» рукопожатия делают постоянную подпись WireGuard нечитаемой для DPI. Sephiroth запускает его как sidecar (отдельный процесс рядом с ядром): вы выбираете в Forge протокол amnezia-wg, панель создаёт пару ключей сервера и публичный ключ каждого клиента, берёт параметры обфускации по умолчанию или вручную и выдаёт готовые к запуску .conf-файлы сервера и клиента.

ПараметрЧто означаетПо умолчанию
JcСколько junk-пакетов отправляется перед каждым рукопожатием (шум для DPI)4
Jmin / JmaxДиапазон случайного размера junk-пакетов40 / 70
S1 / S2Число init/response-пакетов с бессмысленным содержимым15 / 60
H1–H4Кастомные «магии» рукопожатия (вместо знаменитой подписи WireGuard)авто
MTUЕдиница передачи; 1420 по умолчанию для свободного прохода туннеля1420
Доставка клиенту — 2 пути
1) .conf-файл, готовый к импорту в приложение Amnezia (свой приватный ключ у каждого пользователя, ключ сервера не раскрывается) — копируется/скачивается из портала подписки и диалога подписки. 2) Ссылка wireguard:// с параметрами jc/jmin/jmax/s1/s2/h1-h4 — v2rayN, NekoBox и Hiddify разбирают её напрямую («вторая ссылка» в Autopilot и Forge).
Что на стороне сервера?
Панель пишет конфиг, совместимый с awg-quick, в db/core/sidecars/{tag}.conf (адрес 172.16.0.1/24, по одному [Peer] на каждого активного клиента со своим AllowedIPs) и при наличии бинарника запускает его сама. Порядок поиска бинарника: запиннованный админом путь → awg-quick → amneziawg-go.
✓ Даже без бинарника вы ничего не теряете

На серверах, где awg не установлен, панель продолжает обычную работу и полностью пишет .conf-файлы сервера и клиента; установка awg-quick (или закрепление sidecarAwgBin в API настроек) поднимает тот же конфиг без изменений — а Config Doctor честно предупредит, если два inbound-а WG/AWG используют один приватный ключ.

SECTION 04 — THE FORGE

04Создание inbound в Forge

«Forge» — диалог создания/редактирования inbound-а; умная форма, которая прямо во время ввода собирает ссылку подписки и QR вживую в боковой панели рядом. Порядок работы:

  1. Выберите протокол (9 вариантов; каждый поясняется прямо под полем).
  2. Во вкладке General: тег, порт и адрес прослушивания — с двумя волшебными кнопками, представленными ниже.
  3. Вкладки Transport и Security: транспорт + none/TLS/REALITY со всеми деталями (SNI, ALPN, fingerprint, shortId и т.д.).
  4. В расширенном режиме: Fallbacks как настоящий массив и Sniffing/Mux.
  5. Сохранить → inbound встаёт в сеть карточек с полосой трафика и чипами ограничений; клиентов добавляйте там же.

Быстрое создание (Quick Create)

Если не хочется возиться с формой, нажмите один из готовых пресетов в сетке «Быстрого создания»: VLESS + REALITY :443VMess + WS + TLSЛокальный SOCKS5Комбо на одном порту и другие — покажется сводка настроек, подтверждаете — и готово.

SECTION 04 — THE FORGE · AUTOFILL

04Автоопределение IP и свободного порта

Две маленькие кнопки в Forge избавляют от классических бед «ссылка не работает»:

✛ SERVER-IP AUTO-DETECT
Рядом с полем «listen»: меню с определённым публичным IP, приватными IP и 0.0.0.0. Публичный IP приходит от echo-сервисов (с кэшем на 10 минут) — и главное: при выборе ссылка подписки в тот же момент переключается на реальный IP, чтобы 0.0.0.0 никогда не просочился в клиентскую ссылку.
✦ FREE-PORT WAND
Рядом с полем «порт»: волшебная палочка, предлагающая первый свободный порт (порт панели +1 и +2, затем 8443/443/2053/2087/2096/8880). Ошибок «порт занят» и дублирующихся портов больше нет.
⚠ Совет профессионала

Если вы за CDN или обратным прокси, поставьте «listen» в 0.0.0.0 или приватный IP — в клиентских ссылках окажется только публичный IP/домен; Forge держит эти два понятия раздельно.

SECTION 04 — THE FORGE · AUTOPILOT

04Autopilot — флот конфигов в один клик

Вместо создания inbound-ов по одному мастер Autopilot собирает мультипротокольный флот в три шага — с автоматическим распределением портов, наследованием шаблона и ссылкой подписки на выходе. Кнопка «Autopilot» — рядом с «Новый inbound» во вкладке inbound-ов.

  1. Источник: «Клонировать существующий inbound» (полный клон транспорта/безопасности/пользователей шаблона) или «Выбрать несколько протоколов» (свежие inbound-ы с новыми ключами).
  2. План сборки: таблица протоколов с редактируемым портом, движком исполнения и колонкой пользователей; переключатель TLS, «начальный порт» и «последовательное распределение» — здесь же.
  3. Сборка: один атомарный POST; строки получают галочки прямо здесь, а в конце приходит отчёт со ссылкой подписки для каждого inbound-а.
PORT ALLOCATOR
Сначала публичные порты (443, 8443, 2053, 2083, 2087), затем последовательные; занятые и дубли пропускаются.
ENGINE MAP
VLESS/VMess/Trojan/SS ← стрим ядра Xray · Hysteria2/TUIC/Mixed ← движок sing-box · MTProto ← sidecar mtg · WireGuard/AWG ← sidecar WireGuard.
USERS
В мультипротокольном режиме — новый пользователь на каждый inbound или одна общая учётная запись на все; в клоне копируются пользователи шаблона.
◈ Атомарно и с откатом

Если протокол падает посреди сборки, созданное откатывается, порты освобождаются; в отчёте ссылка подписки и «вторая ссылка» (.conf AmneziaWG) — в один клик.

SECTION 05 — USERS & SUBSCRIPTIONS

05Пользователи и подписки

Каждый пользователь — настоящий подписчик: квота трафика, день истечения, лимит IP и несколько inbound-ов одновременно. Таблица пользователей показывает живую полосу расхода, статус активен/истёк и умные чипы:

  • Чип прогноза расхода: «≈4 дня до лимита · 3,2 ГБ/день» — скорость сжигания = расход, делённый на возраст аккаунта (таблица истории не нужна); ниже 7 дней — янтарный, ниже 3 — красный.
  • Цикл сброса: недельные/месячные квоты сбрасываются встроенным cron автоматически, и истёкший пользователь одновременно деактивируется.
  • Ожидание (On-Hold) и автопродление: часы подписки стартуют не с момента создания, а с первого подключения пользователя; при автопродлении окно обновляется в день истечения — подробности на странице «Жизненный цикл».
  • Лимит устройств (HWID) и лимит IP: число устройств подписки действует в портале подписки, а лимит IP (опционально, в духе fail2ban) автоматически отключает превысившего пользователя.
  • Доступ к inbound-ам: пользователь может сидеть на нескольких inbound-ах; ключ каждой посадки (UUID/пароль/flow) управляется там же.
◈ Реальное применение лимитов

Переключатель «Применять лимит IP» в карточке ядра автоматически отключает превысивших лимит в 10-минутных окнах (выкл = только предупреждение); лимит устройств HWID применяется в портале подписки — 13-е устройство останавливается страницей «Достигнут лимит устройств», админ снимает его кнопкой «Сбросить устройства».

SECTION 05 — USERS · LIFECYCLE & BULK

05Жизненный цикл — ожидание, автопродление, массовые операции

Sephiroth ведёт жизнь подписки как настоящую продажу: аккаунт может не считаться до первого подключения, при истечении — обновить сам себя вместо отключения, а десятки пользователей управляются одним кликом.

Ожидание (ON-HOLD)
С переключателем «Ожидание (старт с первого подключения)» аккаунт получает статус В ожидании первого подключения: без обратного отсчёта, день истечения фиксируется от первого реального подключения (первая подписка или первый трафик). Возврат в «Ожидание» стирает якорь — отсчёт пойдёт заново.
Автопродление (AUTO-RENEW)
С переключателем «Автопродление» в момент истечения встроенный cron панели открывает целое новое окно с той же точки, обнуляет расход, поднимает счётчик «Продлений» и вместо деактивации оставляет подписку живой — модель «скользящей подписки» без участия админа.

SECTION 05 — SUBSCRIPTION PORTAL

05Брендированный портал подписки

У каждого пользователя своя ссылка подписки: /sub/<subId>. Страница подписки — брендированный «орбитальный пропуск»: полоса расхода, оставшиеся дни и импорт в один клик в популярные приложения. Саб-группы собирают нескольких пользователей за одной ссылкой с паролем. Бренд страницы — имя/логотип/акцентный цвет — автоматически берётся из настроек панели и из профиля каждого реселлера; полный white-label вплоть до подписи в футере.

SECTION 08 — SECURITY

08Безопасность

Двухфакторный вход TOTP
Реализация RFC-6238 без зависимостей (SHA-1, 6 цифр, окно ±1). Регистрация по QR + код подтверждения; для отключения тоже нужен код — украденная сессия не выключит 2FA. После пароля вход запрашивает код.
Анти-брутфорс
5 неудачных попыток за 5 минут = блокировка IP с живым обратным отсчётом на экране входа; полный журнал попыток — в «Событиях».
Ключ восстановления
Ключ SEPH-XXXX-XXXX-XXXX показывается только один раз и вращается по вашему желанию — забыть пароль означает простой вход, а не потерю панели.
Сессии
httpOnly-кука, подписанная HMAC; «отозвать все сессии» вращает secret и делает недействительными все куки. Режим куки SEPH_COOKIE_SECURE=auto сам определяет, находитесь ли вы за HTTPS.
Бэкап по расписанию
Каждые 24 часа полный JSON-экспорт в db/backups/ с хранением 1–30 файлов (старые удаляются) + немедленный запуск, скачивание и удаление из интерфейса. Ручной бэкап/восстановление с подтверждением RESTORE тоже есть.
Обновление ПО
Кнопка «проверить → установить → перезапустить» внутри панели: апдейтер работает отдельным процессом, публикует статус в файл состояния, и панель до перезапуска продолжает работать на прежнем коде. non-git-установки обновляются через CLI.

SECTION 09 — TELEGRAM

09Telegram

Вечный вопрос «как провести Telegram через блокировки?» решён в самой панели — полным набором инструментов и честными примечаниями:

1) Набор SOCKS5-прокси

Когда вы создаёте SOCKS5 inbound в Forge, открывается блок «прокси Telegram»: помимо стандартной ссылки — две нативные Telegram-ссылки + QR: t.me/socks?server=…&port=…&user=…&pass=… и tg://socks?… — пользователь нажимает один раз, и Telegram принимает прокси.

2) Инструмент MTProto (Настройки → Система)

Для более враждебных сетей встроенный инструмент «MTProto-прокси» создаёт настоящий secret: задаёте хост, порт и режим dd (маскировка доменом) или plain, получаете secret + ссылки tg://proxy и t.me/proxy + QR, а готовые команды запуска mtg v2 (Docker) — в той же карточке.

⚠ Техническая честность — что нужно знать

1) SOCKS5 в Telegram без маскировки — виден DPI; в строгих сетях — MTProto. 2) Xray удалил MTProto-inbound в v24.10 — Sephiroth честно даёт sidecar mtg (раздел 03) и генератор secret.

3) Магазин Telegram — режимы бота

У бота три режима: Консоль, Уведомления и Магазин — продажа прямо в Telegram: пользователь выбирает язык и шаблон продажи, платит через ZarinPal или чеком card-to-card, админ подтверждает в чате — заказ мгновенно проходит провижининг, ссылка /sub/ доставляется автоматически.

SECTION 10 — BUSINESS

10Бизнес — реселлеры и шлюзы

Sephiroth — единственная панель в списках сравнения с полноценной реселлерской системой — тем, чего нет у 3x-ui/Marzban/Remnawave:

Реселлеры (Resellers)

  • Вторая роль с независимой авторизацией: реселлер входит под своей учёткой, и в навигации видит только «Пользователей».
  • Жёсткие квоты: потолок числа пользователей и выделенного трафика — превышение отклоняется на уровне API (не только интерфейса) с кодом 403.
  • Скоуп-списки: реселлер видит только своих пользователей, и даже подделанный запрос теряет чужих пользователей в ответе 404 (без раскрытия их существования).
  • Бренд каждого реселлера (white-label): имя бренда, адрес логотипа и свой акцентный цвет в диалоге реселлера — страница подписки его пользователей рендерится с его брендом (без бренда применяется бренд панели).
  • Полосы мониторинга для админа: по каждому реселлеру видно, сколько пользователей из скольких квот и сколько гигабайт из скольких гигабайт израсходовано.

Шаблоны продаж (Sale Templates)

Готовые пакеты («Starter 50G», «Pro 200G», …) появляются в диалоге создания пользователя чипами в один клик и разом заполняют квоту/срок/лимит IP — продавцы собирают правильный пакет, не думая о числах.

11Развёртывание — установка одной строкой и CLI

На любом Linux-сервере (Debian/Ubuntu/RHEL/Alpine/Arch, x86_64 и arm64) — всего одна строка:

SEPH_NONINTERACTIVE=1 bash install.sh

Что создаёт скрипт?

  • /opt/sephiroth — исходники + сборка SPA (vite) и однофайловый бандл server.cjs (esbuild); затем node_modules удаляется → запуск без зависимостей.

  • Ужесточённый systemd-сервис: NoNewPrivileges, ProtectSystem=full, PrivateTmp — а в окружении без systemd режим демона через CLI.
  • Итог установки: адрес панели и пароли печатаются и сохраняются в install-result.env с правами 0600. Node 22 при отсутствии тоже устанавливается (NodeSource → репозиторий дистрибутива → официальный пиннованный tarball).

services:

1) Смените пароль по умолчанию (Профиль → Безопасность). 2) Сохраните ключ восстановления в надёжном месте. 3) Включите 2FA. 4) Сделайте ручной бэкап, чтобы один раз потренировать восстановление. 5) В production включите реальный драйвер Xray в карточке «Ядро».

SECTION 12 — RESPONSIVE

12Мобильные устройства и адаптивность

Все 13 видов панели переработаны и для ширины 390 пикселей: таблицы превращаются в стопки карточек, верхняя панель сворачивается, а большие диалоги (как Forge) переходят на вертикальную прокрутку с полями во всю ширину — в обеих направлениях LTR и RTL, без горизонтального переполнения (проверено автоматическим аудитом раскладки).

MOBILE-FIRST TOUCHES
Глобальный поиск и палитра команд Ctrl+K доступны и на мобильном; переход между видами — через ту же верхнюю навигацию и кнопки быстрых действий панели.

SECTION 13 — TROUBLESHOOTING & FAQ

13Устранение неполадок · FAQ

ВопросКороткий ответ
Получаю «порт занят»Нажмите кнопку-волшебную палочку ✦ в Forge — предложится первый свободный порт; для ручной проверки: ss -tlnp | grep <port>
Загрузка бинарника Xray не удаётсяЗадайте путь к бинарнику вручную или запиньте версию в карточке «Ядро»; до тех пор панель продолжает обычную работу на Симуляторе.
Цифры трафика Симулятора отличаются от реальных?Да — телеметрия Симулятора показательная. Настоящая статистика per-user приходит только от реального драйвера Xray (раздел 07).
Забыл пароль администратораНа сервере: sephiroth → пункт 8 (смена пароля); или используйте «ключ восстановления» на экране входа.
Как восстановить бэкап?Настройки → Восстановление → JSON-файл + подтверждение RESTORE; или на сервере: sephiroth → пункт 11. Восстановление выполняется одной транзакцией, аккаунт администратора остаётся нетронутым.
Как включить HTTPS?Поставьте обратный прокси (Nginx/Caddy) с TLS; у защищённой куки есть режим auto, и через x-forwarded-proto она сама становится Secure.
Есть только один порт (бесплатный хостинг)Соберите пресет «Комбо на одном порту» (раздел 03): несколько протоколов с fallback на одном порту + панель на /panel.
После изменения панель всё ещё работает на старом кодеЭто нормально — внутрипанельное обновление ждёт «перезапуска», чтобы не рвать сессии; нажмите кнопку перезапуска.
Не поднимается inbound AmneziaWGБинарника awg нет на сервере; панель и так пишет оба .conf. awg-quick или путь в sidecarAwgBin поднимает тот же конфиг.
Не приходит дневной отчёт о продажахВключите в Настройки → Telegram-бот, задайте токен + ID чата админа; «Отправить тестовый дневной отчёт» отправляет его сразу.
✓ Быстрый набор для диагностики

sephiroth logs — лог сервиса · sephiroth status — состояние · живой лог ядра в карточке «Ядро / Xray» · отчёт Config Doctor, чтобы почистить конфиг · лента «События», чтобы видеть, кто что сделал.

Впереди

  • Брендинг групп — собственный бренд для каждой саб-группы (в дополнение к панели и реселлеру).
