SECTION 01 — INTRODUCTION

01简介 — Sephiroth 是什么？

Sephiroth 是一个面向 Xray 的完整管理面板：入站、用户与订阅、实时统计、安全与备份 — 全部汇聚在单一 Node.js 进程中。既不需要 MySQL 也不需要 Postgres；数据以原子方式保存在一个 JSON 文件里，界面也通过同一端口对外服务。

DESIGN LANGUAGE
黑曜石 + 玻璃质感青色
背景 #060b0f，点缀 #22d8ee；玻璃卡片、环形轨道与星空 — 这套视觉语言在全部 6 款主题中保持一致。

ZERO-DEP RUNTIME
零 node_modules 依赖
生产模式下，整个后端构建为单文件包（server.cjs）；对小主机与单端口环境堪称理想。

Sephiroth 为想要精细控制的个人服务器管理员、需要代理分销与支付渠道的卖家、以及想要一款美观轻量的波斯语面板的自托管用户而打造 — 内置 Socket.IO 实时遥测、Ctrl+K 组合命令面板与应用内实战指南。

SECTION 02 — ARCHITECTURE

02面板架构

整个面板就是一个进程：Express 服务器（REST API）与构建好的 React 界面（SPA）共用同一端口，Socket.IO 负责推送实时遥测（CPU/RAM/磁盘、入站状态、事件）。网络核心有两种模式：模拟器（默认；安全、无需二进制）或真实 Xray 驱动（详见第 07 节）。

SECTION 03 — PROTOCOLS

03协议与传输层

Sephiroth 锻造厂将 13 种入站协议与 6 种传输方式、3 层安全机制自由组合；订阅链接、二维码、.conf 文件与内核输出都由同一组合自动生成。

协议特性与用途
VLESS现代轻量；支持 xtls-rprx-vision flow — 与 REALITY 是黄金搭档
VMess经典通用；适合 CDN 与 WebSocket
Trojan伪装成普通 HTTPS 流量
Shadowsocks简单快速；知名加密算法 + 2022-blake3（SS2022）加密，含密钥长度校验
Hysteria2基于 QUIC/UDP，适合高带宽或高丢包网络 — 独立 sidecar
TUICQUIC 隧道 + BBR 拥塞控制 — sing-box 引擎
WireGuard官方隧道，含私钥/公钥与可调 MTU — sidecar
AmneziaWG抗审查 WireGuard，带混淆参数 — 见下一页
MixedHTTP+SOCKS 合并端口，sing-box 引擎 — 自动驾驶首选
MTProto原生 Telegram 代理，mtg sidecar（自动 secret）
SOCKS5 / HTTP本地代理，可选鉴权 — 包括“Telegram 代理”（第 09 节）
Dokodemo-door透明端口，用于流量转发（也充当内核的隐藏 API 门）
TRANSPORTS
TCP + headerWebSocketgRPCHTTPUpgradeXHTTPmKCP
每项传输均可配置 path/host/serviceName、early-data 与 mKCP 头类型（srtp/utp/wechat-video/dtls/wireguard/dns）。
SECURITY
noneTLS 1.0–1.3REALITY
ALPN、9 种 fingerprint（chrome/firefox/safari/…）、uTLS；REALITY 支持 dest、serverNames、shortIds 与内置密钥对。

Fallbacks 与“单端口组合”预设

每个 TLS 入站都可以配置 fallback（dest/alpn/path）— 这正是单端口组合预设的基础：多个协议共享一个公共端口（例如 443），面板本身挂在 /panel 路径 — 单端口主机的完整解决方案。

✓ 内核配置自动生成

你在 Forge 中搭建的一切，都会由内核驱动（第 07 节）转换为真实 Xray 配置 — streamSettings、REALITY、sniffing（http/tls/quic/fakerd）、mux 与 fallback，全程无需手工改 JSON。

SECTION 03 — AMNEZIAWG · OBFUSCATED WIREGUARD

03AmneziaWG — 抗审查的 WireGuard

AmneziaWG 就是 WireGuard 加上一项超能力：手工构造的数据包与自定义握手“戏法”会把 WireGuard 的固定签名对 DPI 模糊化。Sephiroth 以 sidecar（内核旁的独立进程）方式运行它：你在 Forge 中选择 amnezia-wg 协议，面板生成服务端密钥对与每个客户端的公钥，混淆参数取默认值或手动填写，并交付开箱即用的服务端与客户端 .conf 文件。

参数含义默认值
Jc每次握手前发送的 junk 包数量（对 DPI 的“佯攻”）4
Jmin / Jmaxjunk 包大小的随机区间40 / 70
S1 / S2携带无意义内容的 init/response 包数量15 / 60
H1–H4自定义握手“戏法”（取代 WireGuard 的著名签名）自动
MTU最大传输单元；默认 1420，便于顺畅穿过隧道1420
交付到客户端 — 两条路径
1）.conf 文件：可直接导入 Amnezia 系应用（每位用户独立私钥，不暴露服务端密钥）— 从订阅门户与订阅对话框复制/下载。2）wireguard:// 链接：带 jc/jmin/jmax/s1/s2/h1-h4 参数 — v2rayN、NekoBox 与 Hiddify 可直接解析（自动驾驶与 Forge 中的“第二链接”）。
服务端一侧会发生什么？
面板把兼容 awg-quick 的配置写入 db/core/sidecars/{tag}.conf（地址 172.16.0.1/24，每个活跃客户端一个 [Peer] 与专属 AllowedIPs），并在二进制可用时自行启动它。二进制的查找顺序：管理员固定路径 ← awg-quick ← amneziawg-go。
✓ 没有二进制也不会损失什么

在未安装 awg 的服务器上，面板照常工作并完整写好服务端与客户端 .conf；安装 awg-quick（或在设置 API 中设定 sidecarAwgBin）后，同一配置无需任何改动即可上线 — 如果两个 WG/AWG 入站复用同一私钥，配置医生也会如实告警。

SECTION 04 — THE FORGE

04用 Forge 创建入站

“Forge”是创建/编辑入站的对话框 — 一个智能表单，输入的同时就会在旁边的侧栏实时生成订阅链接与二维码。操作流程：

  1. 选择协议（9 个选项；每个选项的说明就显示在该字段下方）。
  2. 在 General 标签页：填写标签、端口与监听地址 — 旁边还有两个下文介绍的魔法按钮。
  3. Transport 与 Security 标签页：传输方式 + none/TLS/REALITY 的全部细节（SNI、ALPN、fingerprint、shortId 等）。
  4. 高级模式下：Fallbacks 以真实数组形式配置，另有 Sniffing/Mux。
  5. 保存 → 入站出现在卡片网络中，带流量条与限额徽章；客户端可直接在此添加。

快速创建（Quick Create）

懒得填长表单？直接在“快速创建”网格中点击一个现成预设：VLESS + REALITY :443VMess + WS + TLS本地 SOCKS5单端口组合等 — 显示配置摘要，确认即完成。

SECTION 04 — THE FORGE · AUTOFILL

04自动检测 IP 与空闲端口

Forge 里的两个小按钮，专门根治“链接用不了”这类经典麻烦：

✛ SERVER-IP AUTO-DETECT
在“监听”字段旁：一个菜单，包含自动探测到的公网 IP、内网 IP 与 0.0.0.0。公网 IP 来自 echo 服务（带 10 分钟缓存）— 更关键的是：一旦选中，订阅链接会立刻切换为真实 IP，确保 0.0.0.0 永远不会混入客户端链接。
✦ FREE-PORT WAND
在“端口”字段旁：魔棒一键推荐首个空闲端口（面板端口 +1 和 +2，然后依次尝试 8443/443/2053/2087/2096/8880）。从此告别“端口被占用”报错与端口冲突。
⚠ 专业提示

如果你在 CDN 或反向代理之后，把“监听”保持为 0.0.0.0 或内网 IP 即可，客户端链接中只会出现公网 IP/域名 — Forge 会把这两个概念分开。

SECTION 04 — THE FORGE · AUTOPILOT

04自动驾驶 — 一键搭起整支配置舰队

与其逐个创建入站，自动驾驶向导三步就能搭起一支多协议舰队 — 自动分配端口、继承模板、输出订阅链接。“自动驾驶”按钮就在配置视图“新建配置”旁边。

  1. 来源：“对齐现有入站”（完整克隆模板的传输/安全/用户）或“选择多个协议”（全新入站 + 全新密钥）。
  2. 构建计划：协议表格，端口可编辑，含运行引擎与用户列；TLS 开关、“起始端口”与“连续分配”也在这里。
  3. 构建：一次原子 POST；行内就地打勾，最后给出带每个入站订阅链接的报告。
PORT ALLOCATOR
先分配首选公共端口（443、8443、2053、2083、2087），再依次取连续端口；被占用与重复的端口自动跳过。
ENGINE MAP
VLESS/VMess/Trojan/SS ← Xray 内核流 · Hysteria2/TUIC/Mixed ← sing-box 引擎 · MTProto ← mtg sidecar · WireGuard/AWG ← WireGuard sidecar。
USERS
多协议模式：每个入站配“一名新用户”，或全体共用“一个身份”；克隆模式则复制模板用户。
◈ 原子化、可回滚

若某个协议在构建中途失败，已完成的部分会被回收、端口保持空闲；报告中的订阅链接与“第二链接”（AmneziaWG 的 .conf 文件）每行都可一键复制。

SECTION 05 — USERS & SUBSCRIPTIONS

05用户与订阅

每个用户都是一名真实订阅者：流量配额、到期日、IP 数限制，以及可同时绑定多个入站。用户表格提供实时用量条、有效/过期状态与智能徽章：

  • 用量预测徽章：“≈4 天到顶 · 3.2 GB/天” — 燃烧率由累计用量除以账户存活天数得出（无需历史表）；低于 7 天变琥珀色，低于 3 天变红。
  • 重置周期：周/月配额由内置 cron 自动重置，过期用户同时被停用。
  • 等待中（On-Hold）与自动续期：订阅时钟不再从创建那一刻起算，而是从用户首次连接开始；开启自动续期后，到期时订阅窗口自动续新 — 详见“生命周期”一页。
  • 设备上限（HWID）与 IP 上限：每份订阅的设备数在订阅门户执行；同时启用的 IP 上限（可选，fail2ban 风格）会自动切断超额用户。
  • 绑定入站：每个用户可同时挂载到多个入站；每条绑定的密钥（UUID/密码/flow）都在同一处管理。
◈ 真实限额执行

Core 卡片中的“执行 IP 上限”开关，会以 10 分钟为窗口自动停用超限用户（关闭 = 仅告警）；HWID 设备上限则在订阅门户执行 — 第 13 台设备会看到“设备数已达上限”页面，管理员用“重置设备”即可解除。

SECTION 05 — USERS · LIFECYCLE & BULK

05用户生命周期 — 等待中、自动续期与批量操作

Sephiroth 像经营真实销售那样管理订阅的生命周期：账户可以在首次连接前不计时，到期时自行续新而非断开，几十个用户也能一键管理。

等待中（ON-HOLD）
打开“等待中（以首次连接开始）”开关后，账户会以 等待首次连接 状态创建：看不到任何倒计时，到期日锁定在用户的首次真实连接（首次订阅或首个流量）上。重新切回“等待中”也会清除锚点，下次连接时重新起算。
自动续期（AUTO-RENEW）
打开“自动续期”后，到期那一刻面板内置 cron 会从同一点开启一个完整的新窗口、清零用量、把“续期次数”加一 — 订阅不停用、继续存活 — 无需管理员介入的“滚动订阅”模式。

批量操作 — 对任意数量的用户执行 11 种动作

动作效果动作效果
启用 / 停用账户状态续期从现在起全新窗口 + 用量清零
流量清零用量 ← 0保持等待 / 移出等待首次连接起算锚点
自动续期 开/关滚动订阅开关重置设备清除 HWID 注册记录
设置限额天数/流量/IP — 留空即不改动删除带确认对话框
  • 批量创建：用户名前缀 + 数量（至多 100），沿用相同限额；用户导入/导出同样支持 JSON。
  • 设备（HWID）：每个用户的抽屉里列出已注册设备（UA + 最近活跃）与“重置设备”按钮 — 第 13 台设备在门户会被“设备数已达上限”页面拦下。
✓ 一切都有通知

等待账户激活（首次连接）、自动续期、临近到期与登录失败 — 全都是通知引擎的事件（第 08 节）：顶栏铃铛 + 管理员 Telegram。

SECTION 05 — SUBSCRIPTION PORTAL

SECTION 06 — CONFIG DOCTOR

06配置医生

配置医生是 Sephiroth 的独家特性：对整个面板进行 16 项扫描，在用户察觉之前就发现问题，并为每一项给出“标题 + 说明 + 解决方案”。得分按满分 100 计算：

score = 100 − 12×危险 − 5×警告 − 1×提示  →  评级 A 至 D

入站（8 项检查）
无鉴权的开放 SOCKS/HTTP 代理 · 无证书的 TLS · 不完整的 REALITY（dest/serverNames/shortIds/密钥）· 失效的 fallback · WireGuard 私钥重复使用 · 特权端口（<1024）· 已过期入站 · 已停用入站
用户（6 项检查）
已过期但仍处于激活状态 · 临近到期（≤3 天）· 配额耗尽 · 用量 ≥90% · 无法访问任何入站的“幽灵”账户 · 绑定在已停用入站上的用户
路由（2 项检查）
死规则（出站不存在）与无条件空规则 — 它们会无声地吞噬流量或拒绝一切。
扫描输出
得分环 + 评级 + 严重度徽章（危险/警告/提示），每条发现均附详细说明与建议修复按钮。所有文案已翻译为 6 种语言。

SECTION 07 — REAL XRAY CORE

07真实 Xray 内核

SECTION 08 — SECURITY

08安全性

TOTP 两步验证
零依赖实现 RFC-6238（SHA-1、6 位数字、±1 窗口）。通过二维码 + 验证码开启；关闭同样需要验证码，防止被盗会话关掉 2FA。登录页在密码之后再要求输入验证码。
防暴力破解
5 分钟内 5 次失败尝试 = 锁定 IP，登录页实时倒计时；全部尝试记录见“活动”日志。
恢复密钥
恢复密钥 SEPH-XXXX-XXXX-XXXX 仅显示一次，可随时轮换 — 忘记密码只是多走一步简单登录，而不是丢掉面板。
会话
基于 HMAC 签名的 httpOnly Cookie；“吊销所有会话”会轮换 secret，使全部 Cookie 失效。SEPH_COOKIE_SECURE=auto 模式会自动判断你是否处于 HTTPS 之后。
定时备份
每 24 小时在 db/backups/ 生成完整 JSON 备份，保留 1–30 份（自动清理旧备份）+ 立即执行、下载与界面内删除。也支持手动备份/恢复，恢复需输入 RESTORE 确认。
软件更新
“检查 → 安装 → 重启”按钮就在面板内：更新脚本独立于主进程运行，状态写入状态文件，重启前面板继续以旧代码服务。非 git 安装也可通过 CLI 更新。

SECTION 09 — TELEGRAM

09Telegram

“怎么让 Telegram 穿透封锁？”这个老问题在面板内就有答案 — 一套完整套件加坦诚的注意事项：

1）SOCKS5 代理套件

在 Forge 中创建 SOCKS5 入站后，“Telegram 代理”区块随之展开：除标准链接外还提供两个 Telegram 原生链接 + 二维码：t.me/socks?server=…&port=…&user=…&pass=… 与 tg://socks?… — 用户只需轻点一下，Telegram 即接受该代理。

2）MTProto 工具（设置 → 系统）

面向更敌意的网络，内置“MTProto 代理”工具会生成真实密钥：输入主机、端口与 dd（域名伪装）或 plain 模式，即可拿到密钥 + tg://proxy 与 t.me/proxy 链接 + 二维码；同一卡片内还附有运行 mtg v2（Docker）的现成命令。

⚠ 技术坦诚 — 你需要知道的事

1）Telegram 中的 SOCKS5 没有伪装，对 DPI 可见；严苛网络请使用 MTProto。2）Xray 自 v24.10 起已移除 MTProto 入站 — 因此 Sephiroth 不做不实宣传，而是提供独立 mtg sidecar（第 03 节）与密钥生成工具。

3）Telegram 商店 — 机器人模式

Sephiroth 机器人有三种模式：控制台、通知与商店 — 在 Telegram 内完成完整销售：用户选择语言、浏览销售模板，用 ZarinPal 支付或发送卡到卡凭条照片；管理员在聊天中批准后，订单即刻完成开通，/sub/ 订阅链接自动送达。

机器人支付网关
ZarinPal v4 自动发起/验证 · 卡到卡凭条照片审批 · 按模板定价（priceToman）· 六种语言的机器人文案。
机器人通知

10商业 — 代理与支付渠道

在各类对比清单中，Sephiroth 是唯一拥有完整代理分销体系的面板 — 3x-ui/Marzban/Remnawave 均不具备：

代理（Resellers）

  • 独立认证的第二角色：代理使用自己的账号登录，导航中只看到“用户”。
  • 硬配额：用户数上限与分配流量上限 — 超额会在 API 层面（而不仅是界面）以 403 拒绝。

销售套餐模板（Sale Templates）

SECTION 11 — DEPLOYMENT

11部署 — 一行安装与 CLI

在任何 Linux 服务器（Debian/Ubuntu/RHEL/Alpine/Arch，x86_64 与 arm64）上只需一行：

# 交互式安装（会询问端口/用户名/密码）
bash <(curl -Ls https://raw.githubusercontent.com/Edsel-Rahimi/Sephiroth/main/install.sh)

# 安装固定版本
bash <(curl -Ls https://raw.githubusercontent.com/Edsel-Rahimi/Sephiroth/main/install.sh) v2.6.0

# 免交互安装（CI/脚本）— 输出：/etc/sephiroth/install-result.env
SEPH_NONINTERACTIVE=1 bash install.sh

安装脚本做了什么？

  • /opt/sephiroth — 源码 + SPA 构建（vite）与单文件打包 server.cjs（esbuild）；随后删除 node_modules → 零依赖运行。
  • /etc/sephiroth/sephiroth.env — 随机空闲端口（20580–21000）、16 位随机密码与 SEPH_COOKIE_SECURE=auto（重复执行会保留已有配置）。
  • 严格的 systemd 服务：NoNewPrivileges、ProtectSystem=full、PrivateTmp — 在无 systemd 环境中则提供 CLI 守护进程模式。
  • 安装摘要：面板地址与凭据以 0600 权限打印并保存到 install-result.env。若缺失 Node 22 也会自动安装（NodeSource → 发行版仓库 → 官方固定版本 tarball）。

11部署 — Docker 与更新

官方多阶段镜像基于 node:22-alpine 构建：第一阶段完成 SPA 构建 + esbuild，第二阶段仅保留 server.cjs + dist/ — 无源码、无 node_modules。内置健康检查指向 /api/auth/session，并使用 /app/db 卷持久化数据。

# 最快捷方式
docker run -d --name sephiroth -p 3000:3000 -v sephiroth_data:/app/db \
  ghcr.io/edsel-rahimi/sephiroth:latest

# docker-compose.yml
services:
  sephiroth:
    image: ghcr.io/edsel-rahimi/sephiroth:latest   # 或固定版本：:v2.6.0
    ports: [ "${SEPH_PORT:-3000}:3000" ]
    environment:
      SEPHIROTH_ADMIN_USER: ${SEPHIROTH_ADMIN_USER:-admin}
      SEPHIROTH_ADMIN_PASS: ${SEPHIROTH_ADMIN_PASS:-sephiroth}  # 首次登录后请立即修改！
      SEPH_COOKIE_SECURE: auto
    volumes: [ sephiroth_data:/app/db ]

标签由 GitHub Actions 自动构建并推送到 GHCR：latest 对应 main 分支，语义化版本标签（v2.6.0）— 生产环境建议固定版本。环境变量中的用户名/密码仅在空数据首次启动时注入；之后请只在面板内或通过 CLI 修改。

更新（脚本安装）

SECTION 13 — TROUBLESHOOTING & FAQ

13故障排除 · 常见问题

问题简答
提示“端口被占用”在 Forge 中点击魔棒按钮 ✦ 即可推荐首个空闲端口；手动排查：ss -tlnp | grep <port>
Xray 二进制下载失败在“内核”卡片手动指定二进制路径或固定版本；在此之前面板会用模拟器照常工作。
模拟器的流量数值和真实数据有差别吗？有 — 模拟器只是演示遥测。真实的按用户统计仅来自真实 Xray 驱动（第 07 节）。
忘记了管理员密码在服务器上运行：sephiroth → 选项 8（修改密码）；或在登录页使用“恢复密钥”。
如何恢复备份？设置 → 恢复 → 选择 JSON 文件 + 输入 RESTORE 确认；或在服务器上：sephiroth → 选项 11。恢复在单一事务中完成，管理员账户保持不变。
如何启用 HTTPS？在前端加一个带 TLS 的反向代理（Nginx/Caddy）；安全 Cookie 支持 auto 模式，会依据 x-forwarded-proto 自动变为 Secure。
我只有一个端口（免费主机）使用“单端口组合”预设（第 03 节）：多个协议通过 fallback 共用一个端口 + 面板挂在 /panel。
变更后面板仍在运行旧代码属正常现象 — 面板内更新会等到“重启”才切换，以免中断在线会话；请点击重启按钮。
AmneziaWG 入站起不来服务器上没有 awg 二进制。面板始终会写好服务端与客户端 .conf；安装 awg-quick 或通过 sidecarAwgBin 指定二进制路径，同一配置即可原样启动。
没有收到每日销售日报在 设置 → Telegram 机器人 中打开“每日销售日报”并填入 token 与管理员聊天 ID；“发送测试日报”按钮无需等待 cron，可立即发送。
✓ 快速排障工具箱

sephiroth logs 查看服务日志 · sephiroth status 查看状态 · “内核 / Xray”卡片中有内核实时日志 · 配置医生报告用于清理配置 · “活动”动态可追溯谁做了什么。
