SECTION 01 — INTRODUCTION

01Introduction — What is Sephiroth?

Sephiroth is a complete management panel for Xray: inbounds, users and subscriptions, live statistics, security and backups — all in a single Node.js process. It needs neither MySQL nor Postgres; data is stored in one atomic JSON file and the UI is served from that very same port.

Persian · English · Arabic · 中文 · Türkçe · Русский
Complete, automatic RTL for Persian and Arabic (dialogs and toasts included); switch language from the top bar, no reload.
ZERO-DEP RUNTIME
No node_modules
In production the whole backend builds into a single-file bundle (server.cjs) — ideal for small, single-port hosts.

Sephiroth is built for personal server admins who want precise control, for sellers who need a reseller system and payment gateways, and for self-hosters who want a beautiful, lightweight panel in their own language — with live Socket.IO telemetry, the Ctrl+K command palette and an in-app field guide.

SECTION 03 — AMNEZIAWG · OBFUSCATED WIREGUARD

03AmneziaWG — Censorship-Resistant WireGuard

AmneziaWG is WireGuard with one superpower: hand-crafted junk packets and custom handshake magics that blur WireGuard's fixed signature for DPI. Sephiroth runs it as a sidecar (an independent process beside the core): pick the amnezia-wg protocol in the Forge, and the panel builds the server keypair and each client's public key, takes the obfuscation parameters (defaults or manual) and hands you ready-to-run server and client .conf files.

ParameterWhat it meansDefault
JcNumber of junk packets sent before every handshake (busywork for DPI)4
Jmin / JmaxRandom size range of the junk packets40 / 70
S1 / S2Number of init/response packets padded with meaningless content15 / 60
H1–H4Custom handshake magics (instead of WireGuard's well-known signature)auto
MTUTransmission unit; 1420 by default for an easy ride through the tunnel1420
DELIVERY TO CLIENTS — 2 ROUTES
1) A ready .conf file to import into the Amnezia app (each user's own private key, no server-key leakage) — copy/download from the subscription portal and the subscription dialog. 2) A wireguard:// link carrying the jc/jmin/jmax/s1/s2/h1-h4 parameters — v2rayN, NekoBox and Hiddify parse it directly (the “second link” in Autopilot and the Forge).
WHAT HAPPENS SERVER-SIDE?
The panel writes an awg-quick-compatible config to db/core/sidecars/{tag}.conf (address 172.16.0.1/24, one [Peer] per active client with its own AllowedIPs) and, if the binary is present, launches it itself. Binary lookup order: the admin-pinned path → awg-quick → amneziawg-go.
✓ No binary? You lose nothing

On servers without awg installed, the panel keeps working normally and still writes complete server and client .conf files; installing awg-quick (or setting sidecarAwgBin in the settings API) brings the very same config up unchanged — and Config Doctor honestly warns if a WG and an AWG inbound share a private key.

SECTION 04 — THE FORGE · AUTOFILL

04Automatic IP & Free-Port Detection

Two small buttons in the Forge eliminate the classic “my link doesn't work” headaches:

✛ SERVER-IP AUTO-DETECT
Next to the “listen” field: a menu with the detected public IP, private IPs and 0.0.0.0. The public IP comes from echo services (cached for 10 minutes) — and more importantly, selecting it switches the subscription link to the real IP that instant, so 0.0.0.0 never leaks into a client link.
✦ FREE-PORT WAND
Next to the “port” field: a wand that suggests the first free port (panel port +1 and +2, then 8443/443/2053/2087/2096/8880). No more “port in use” errors or duplicate ports.
⚠ Pro tip

If you sit behind a CDN or reverse proxy, set “listen” to 0.0.0.0 or a private IP; only the public IP/domain lands in client links — the Forge keeps those two concepts apart.

SECTION 04 — THE FORGE · AUTOPILOT

04Autopilot — a Config Fleet in One Click

Instead of building inbounds one by one, the Autopilot wizard assembles a multi-protocol fleet in three steps — with automatic port allocation, template inheritance and the subscription link in the output. The “Autopilot” button sits beside “New config” in the inbounds view.

  1. Source: “mirror an existing inbound” (a full clone of its transport/security/template users) or “pick several protocols” (fresh inbounds with fresh keys).
  2. Build plan: a table of the chosen protocols with an editable port, the run engine and a users column; the TLS switch, “start port” and “contiguous allocation” live right here.
  3. Build: one atomic POST; rows get their checkmark on the spot and a report with each inbound's subscription link arrives at the end.
PORT ALLOCATOR
Preferred public ports first (443, 8443, 2053, 2083, 2087), then contiguous ones; occupied and duplicate ports are skipped automatically.
ENGINE MAP
VLESS/VMess/Trojan/SS → the Xray stream core · Hysteria2/TUIC/Mixed → the sing-box engine · MTProto → the mtg sidecar · WireGuard/AWG → the WireGuard sidecar.
USERS
In multi-protocol mode: “one fresh user” per inbound or “one shared identity” for all — in clone mode, the template's users are copied.
◈ Atomic and rollback-safe

If any protocol fails midway through the build, everything built so far is torn down and the ports stay free; in the report, each row's subscription link + “second link” (the AmneziaWG .conf file) is copied with one click.

SECTION 05 — USERS & SUBSCRIPTIONS

05Users & Subscriptions

Every user is a real subscriber: traffic quota, expiry day, IP limit and several simultaneous inbounds. The users table shows a live usage bar, active/expired status and smart chips:

  • Usage-forecast chip: “≈4 days to cap · 3.2 GB/day” — the burn rate comes from dividing usage by account age (no history table needed); amber under 7 days, red under 3.
  • Reset cycle: weekly/monthly quotas reset automatically via a built-in cron, and expired users are deactivated at the same time.
  • On-hold and auto-renew: the subscription clock starts at the user's first connection, not at the moment the account is created; and with auto-renew, the window refreshes at expiry and keeps serving instead of being cut — details on the “Lifecycle” page.
  • Device (HWID) and IP limits: each subscription's device count is enforced in the sub portal, and the IP limit (optional, fail2ban-style) auto-cuts over-limit users at the same time.
  • Inbound access: a user can ride multiple inbounds; each mount's key (UUID/password/flow) is managed right there.
◈ Real limit enforcement

The IP limit (0 = ∞) is recorded in links and in every client's core output, and the “enforce IP limit” switch in the Core card auto-disables over-limit users in 10-minute windows (off = warn only). The HWID device limit is enforced in the subscription portal — the 13th device sees a “device limit reached” page, and the admin frees it via “Reset devices”.

SECTION 05 — USERS · LIFECYCLE & BULK

05User Lifecycle — On-Hold, Auto-Renew, Bulk Actions

Sephiroth manages a subscription's life like a real sale: an account can stay un-counted until its first connection, renews itself at expiry instead of being cut, and dozens of users are managed in one click.

ON HOLD
With the “on hold (starts on first connect)” switch, the account is created as on hold, starts on first connect: no countdown is shown anywhere and the expiry day locks at the user's first real connection (first sub fetch or first traffic). Switching it back to “on hold” clears the anchor too, so the count restarts at the next connection.
AUTO-RENEW
With the “auto-renew” switch, at the moment of expiry the panel's built-in cron opens a fresh full window from that point, zeroes usage, bumps the “renewals” counter and — instead of deactivating — keeps the subscription alive: the “rolling subscription” pattern with zero admin work.

SECTION 06 — CONFIG DOCTOR

06Config Doctor

Config Doctor is a unique Sephiroth feature: a 16-point scan of the whole panel that finds problems before users discover them and gives every finding “title + explanation + fix”. The score is computed out of 100:

score = 100 − 12×danger − 5×warning − 1×notice  →  grade A to D

Inbounds (8 checks)
Open SOCKS/HTTP proxy without auth · TLS without a certificate · incomplete REALITY (dest/serverNames/shortIds/keys) · broken fallback · WireGuard private-key reuse · privileged port (<1024) · expired inbound · disabled inbound
Users (6 checks)
Expired but still active · near expiry (≤3 days) · exhausted quota · ≥90% usage · a “ghost” account with access to no inbound · a user mounted on a disabled inbound
Routing (2 checks)
A dead rule (nonexistent outbound) and an empty, conditionless rule — the ones that silently swallow traffic or reject everything.
Scan output
A score ring + grade + severity chips (danger/warning/notice) and, for every finding, a precise explanation and a suggested-fix button. All strings are translated into 6 languages.

SECTION 08 — SECURITY

08Security

TOTP two-factor login
A zero-dependency RFC-6238 implementation (SHA-1, 6 digits, ±1 window). Enrollment with QR + a confirmation code; disabling it asks for a code too, so a stolen session can't switch 2FA off. After the password, the login page asks for the code.
Anti-brute-force
5 failed attempts in 5 minutes = the IP gets locked, with a live countdown on the login screen; the full attempt log lives under “Activity”.
Recovery key
The SEPH-XXXX-XXXX-XXXX key is shown only once and can be rotated whenever you like — forgetting the password becomes a simple sign-in, not a lost panel.
Sessions
An httpOnly cookie signed with HMAC; “revoke all sessions” rotates the secret and invalidates every cookie. The SEPH_COOKIE_SECURE=auto cookie mode detects on its own whether you're behind HTTPS.
Scheduled backup
Every 24 hours a full JSON export lands in db/backups/, keeping 1–30 files (oldest pruned) + immediate run, download and deletion from the UI. Manual backup/restore with RESTORE confirmation is there too.
Software update
A “check → install → restart” button inside the panel: the updater runs as a separate process, publishes its status to a status file, and the panel keeps serving the previous code until restart. Non-git installs update via the CLI.

SECTION 09 — TELEGRAM

09Telegram

The eternal question — “how do I get Telegram past censorship?” — is answered inside the panel itself, with a complete suite and some honest notes:

1) The SOCKS5 proxy suite

When you build a SOCKS5 inbound in the Forge, the “Telegram proxy” block opens and, alongside the standard link, gives you two native Telegram links + a QR: t.me/socks?server=…&port=…&user=…&pass=… and tg://socks?… — the user taps once and Telegram accepts the proxy.

2) The MTProto tool (Settings → System)

For more hostile networks, the built-in “MTProto proxy” tool generates a real secret: you choose the host, port and dd (domain camouflage) or plain mode, receive the secret + tg://proxy and t.me/proxy links + QR, and the ready-to-run mtg v2 (Docker) commands sit in the same card.

⚠ Technical honesty — things you should know

1) SOCKS5 in Telegram has no camouflage and is visible to DPI; use MTProto on restrictive networks. 2) Xray itself removed the MTProto inbound in v24.10 — instead of a false claim, Sephiroth ships the independent mtg sidecar (Section 03) + the secret-generation tool.

3) The Telegram shop — bot modes

The Sephiroth bot has three modes: Console (test runs only), Notifications (a worker for alerts) and Sales shop — full selling in Telegram: the user picks a language, sees the sale templates, pays via ZarinPal or sends a card-to-card receipt; the admin approves in chat and the order is provisioned instantly — the /sub/ link is delivered automatically.

Bot gateways
ZarinPal v4 (request / auto-approve) · card-to-card with receipt-photo approval in chat · per-template pricing (priceToman) · bot texts in 6 languages.
Bot notifications
New orders + panel restart to the admin · completed order to the customer · the worker state as a live pill (running/stopped) with the last poll.

SECTION 11 — DEPLOYMENT

11Deployment — One-Line Install & CLI

On any Linux server (Debian/Ubuntu/RHEL/Alpine/Arch, x86_64 and arm64) it's just one line:

# Interactive install (asks for port / user / password)
bash <(curl -Ls https://raw.githubusercontent.com/Edsel-Rahimi/Sephiroth/main/install.sh)

# Install with a pinned version
bash <(curl -Ls https://raw.githubusercontent.com/Edsel-Rahimi/Sephiroth/main/install.sh) v2.6.0

# Unattended install (CI/scripts) — output: /etc/sephiroth/install-result.env
SEPH_NONINTERACTIVE=1 bash install.sh

What does the script create?

  • /opt/sephiroth — the source + SPA build (vite) and the single-file server.cjs bundle (esbuild); then node_modules is wiped → a zero-dependency run.
  • /etc/sephiroth/sephiroth.env — a random free port (20580–21000), a random 16-character password and SEPH_COOKIE_SECURE=auto (re-running preserves existing values).
  • A hardened systemd service: NoNewPrivileges, ProtectSystem=full, PrivateTmp — and on hosts without systemd, a daemon mode via the CLI.
  • Install summary: the panel address and credentials are printed and saved to install-result.env with 0600 permissions. Node 22 is installed too if missing (NodeSource → distro repository → pinned official tarball).

11Deployment — Docker & Updates

The official multi-stage image builds on node:22-alpine: stage one builds the SPA + esbuild bundle, stage two ships only server.cjs + dist/ — no source, no node_modules. A built-in healthcheck hits /api/auth/session and the /app/db volume keeps data persistent.

# Fastest way
docker run -d --name sephiroth -p 3000:3000 -v sephiroth_data:/app/db \
  ghcr.io/edsel-rahimi/sephiroth:latest

# docker-compose.yml
services:
  sephiroth:
    image: ghcr.io/edsel-rahimi/sephiroth:latest   # or pin a version: :v2.6.0
    ports: [ "${SEPH_PORT:-3000}:3000" ]
    environment:
      SEPHIROTH_ADMIN_USER: ${SEPHIROTH_ADMIN_USER:-admin}
      SEPHIROTH_ADMIN_PASS: ${SEPHIROTH_ADMIN_PASS:-sephiroth}  # change it after first login!
      SEPH_COOKIE_SECURE: auto
    volumes: [ sephiroth_data:/app/db ]

Tags are built automatically on GitHub Actions and pushed to GHCR: latest for main plus semantic version tags (v2.6.0) — pinning the version in production is recommended. The env username/password are only seeded on the first boot with empty data; after that, change them only from inside the panel or the CLI.

Updating (script installs)
Re-running install.sh = a safe update: the database, env and passwords stay untouched and the service restarts. The panel itself has an update button too (Section 08). Non-git mode: download the zip + swap server.cjs.
Complete removal
sephiroth uninstall with two confirmations: the service and files are removed; data (db) removal is optional and asked separately.
⚠ Post-install checklist

1) Change the default password (Profile → Security). 2) Store the recovery key somewhere safe. 3) Enable 2FA. 4) Take a manual backup so you've practiced a restore once. 5) In production, enable the Real Xray driver from the “Core” card.

SECTION 13 — TROUBLESHOOTING & FAQ

13Troubleshooting · FAQ

QuestionShort answer
I get “port already in use”Hit the ✦ wand button in the Forge to get the first free port suggested; to check manually: ss -tlnp | grep <port>
The Xray binary download failsSet the binary path manually or pin a version in the “Core” card; until then the panel keeps working normally with the Simulator.
Do Simulator traffic numbers differ from real ones?Yes — the Simulator's telemetry is for display. Real per-user stats come only from the Real Xray driver (Section 07).
I forgot the admin passwordFrom the server: sephiroth → option 8 (change password); or use the “recovery key” on the login page.
How do I restore a backup?Settings → Restore → JSON file + RESTORE confirmation; or on the server: sephiroth → option 11. The restore runs in one transaction and the admin account stays untouched.
How do I enable HTTPS?Put a reverse proxy (Nginx/Caddy) with TLS in front; the secure cookie has an auto mode and turns Secure by itself via x-forwarded-proto.
I only have one port (free hosting)Build the “Single-Port Combo” preset (Section 03): several protocols with fallback on one port + the panel on /panel.
After a change, the panel still runs old codeThat's normal — the in-panel update waits for “restart” so sessions don't drop; press the restart button.
The AmneziaWG inbound won't come upThe awg binary isn't on the server. The panel always writes the server-side and client .conf files; installing awg-quick or pinning the binary path (setting sidecarAwgBin) brings the same config up unchanged.
The daily sales digest doesn't arriveEnable it in Settings → Telegram bot and set the token + admin chat; the “Send test digest” button sends it right now, without waiting for the cron.
✓ Quick troubleshooting toolbox

sephiroth logs for service logs · sephiroth status for status · the live core log in the “Core / Xray” card · the Config Doctor report to clean up your config · the “Activity” feed to see who did what.
